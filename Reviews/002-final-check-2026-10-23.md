## 1. High: a conflicting-parent completion can still leave a running card at settlement

Locations: `src/subagent.js:224`, `src/subagent.js:247`, `src/subagent.js:501`, `src/subagent.js:655`; tool conflict handling has the same split at `src/subagent.js:772` and `src/subagent.js:800`.

Reproduction through the proxy:

1. Emit parent `agent_start`; start task calls A and B.
2. Emit child `kid` running under A. The bridge renders A's card running.
3. Emit the same child completed with explicit parent B.
4. Emit parent `agent_end`, then `session_settled`.

The conflicting update correctly creates no card under B. However, it marks the registry record finished while A's existing per-call entry remains unfinished. The completion emits no update to A. The proxy then emits `agent_settled` with A's last visible child result still `finished:false`. A running snapshot under A also fails to repair this disagreement because it reuses the existing unfinished entry. An interrupt instead can incorrectly label the already-completed child aborted and cancel it again.

This preserves the original zombie mechanism under a new input sequence: known terminal information exists before finalization but never reaches the recorded owner's card. It prevents a full sign-off on US10/FR17 and the terminal-lifecycle claims.

Required correction: keep parent ownership frozen, but update lifecycle through one canonical child state and project the terminal result to the recorded owner's card. Conflict handling must not update only the registry while leaving the render entry running. Cover terminal conflicts across all five observation paths, natural settlement, and interruption.

## 2. Medium: a later terminal tool observation can erase the failed/interrupted outcome

Location: `src/subagent.js:872` and `src/subagent.js:880`.

Reproduction through the proxy:

1. Start task A; emit `kid` with lifecycle status `failed` under A.
2. The outgoing result is `finished:true, stopReason:"error", exitCode:1`.
3. Emit a tool update for A with the same child and status `completed`.
4. The outgoing result is now only `finished:true`; `stopReason` and `exitCode` are absent.

The code copies the tracked outcome back into the outgoing result only when that result is not already finished. A contradictory terminal tool result therefore bypasses the preservation path. Other combinations can also overwrite the tracked stop reason. The same issue applies to an aborted child followed by a completed tool record.

Required correction: preserve the established terminal outcome and always project all terminal fields from canonical state, including when the incoming tool record already says `finished:true`. Add terminal-to-terminal channel permutations, not only terminal-to-running regressions.
